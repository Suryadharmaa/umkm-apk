# Existing Android UX audit

Baseline `19f649b`. `WarungApp.kt` owns routes and action dispatch, `Design.kt` owns a light Material 3 theme, and feature screens use existing state and events. This is an inspection of code and checked-in baseline images. Severity denotes potential use impact, not a reproduced crash. **High** means an incorrect financial reading or a blocked core task. **Medium** means repeat friction, weak scanning, or inconsistency.

| `data-tools` · `DataToolsScreen.kt` | Backup/password, native picker cancel/failure, explicitly confirmed empty-db restore with distinct reopen outcomes, dataset/period CSV and plaintext disclosure. | Three similar weight cards and distant feedback → task groups, local system picker, prominent outcome banner and protected password dialog. | High |

Across all routes, maintain the five destination IDs, back-stack behavior, exact integer formatting and known-zero semantics. Offline is the normal operating mode. Loading replaces a single region without placeholder values. Recoverable errors retain inputs where currently allowed. A successful event is shown only when the corresponding existing state is committed. System picker denial/cancellation never implies a saved file. App restart reveals persisted drafts, pending sales and posted receipts. Inline designs must survive long names, large amounts and increased text, without implying transient passwords or drafts are durable.
