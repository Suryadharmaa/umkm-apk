# Screen and design specification

MVP bottom bar: **Beranda · Kasir · Riwayat · Keuangan · Lainnya**. Phase 2 exposes Beranda, Kasir and Katalog as the working destinations. Retain tab state. Checkout, forms, and restore use full-screen routes with an explicit back action. Reconstruct pending screens from saved IDs after process death. Back navigation on a pending QRIS screen returns to history/cart entry while retaining the pending checkout.

| Route | Purpose, primary action, and distinct states |
|---|---|
| Beranda | Real active-product and category counts, quick access to Kasir and Katalog. Show loading, empty, populated, and retryable read failure. Financial summaries enter after payment and ledger features. |
| Setup | Shop name and time zone → Simpan. Invalid, saving, failed, already configured. |
| Kasir | Search/filter catalog, tap a product, sticky cart total → Keranjang. Empty catalog, no results, available, archived product removed on revalidation. |
| Keranjang | Adjust quantities and see itemized total → Pilih pembayaran. Empty, price changed with renewed consent, saving error. |
| Metode pembayaran | Choose Tunai or QRIS. QRIS unavailable links to setup with cart retained. |
| Tunai | Numeric tender, exact-cash shortcut, prominent change → Simpan pembayaran. Insufficient, valid, committing, retry, receipt. |
| QRIS pending | Full merchant asset with quiet zone, amount, merchant identity and status Menunggu konfirmasi → Periksa pembayaran. Resume, missing asset, unresolved payment, cancellation review. |
| Konfirmasi QRIS | Record merchant-side reference, time and amount plus explicit confirmation → Catat konfirmasi manual. Mismatch, duplicate, no evidence, committing, saved. |
| Riwayat | Penjualan and Pembayaran views, date/method/status filters → Detail. Empty history, empty filter, pending/resumable, paid, cancelled, reversed. |
| Detail / struk | Immutable item breakdown, payment and subsequent events → Lihat bukti pencatatan or Koreksi. Pending, posted, cancelled, reversed. Cash receipt shows tender and change. |
| Koreksi / pembatalan | Show consequence and reason. Pending QRIS requires merchant-channel check before cancellation. Paid sale requires completed cash return or external QRIS refund evidence → Catat koreksi. Invalid, unresolved, saved, retry. |
| Keuangan | Account cards for Kas Tunai, QRIS Belum Cair, and Bank → account history, movements, settlement, reports. Uninitialized, empty, populated, reconciliation warning. |
| Akun dan mutasi | Account history → Catat mutasi. Select type, account, amount and note. Show opening already recorded, invalid amount, reversal reason, saved. |
| Pencairan QRIS | Select confirmed eligible payments, payout reference, actual fee and received amount → Catat pencairan. None eligible, mismatch, duplicate, pending commit, saved, detail and reversal. |
| Laporan | Period selector and explicit breakdown → Ekspor. Empty period, populated, read/export failure. |
| Lainnya | Hub → Produk, Kategori, Pengaturan, Cadangan. |
| Produk / kategori | Lists and editors → Simpan or Arsipkan. Empty, duplicate category, invalid price, dependent products, saved, archive confirmation. |
| Pengaturan / QRIS | Shop details and one active merchant profile → Impor QR. Empty, preview plus attestation, unreadable, replacement, inactive. |
| Ekspor / cadangan | Choose period for CSV or create encrypted backup → native document picker. Cancelled, writing, complete after close, partial/write failure. |
| Pulihkan | Entry on first launch/empty data store. Select file, unlock, review counts/shop/date, confirm. Wrong passphrase, corrupt/unsupported, existing records, interrupted, restored. |

Shared asynchronous states include initial loading, inline field errors, durable-save retry preserving input, and success only after commit. Preserve scroll and focus after retry. Give talkback monetary values in context and announce total or error changes. Use icons with labels for primary navigation and support large text without clipping or hiding CTAs.

| Token group | Provisional values |

| Material 3 light palette | Primary #1454BD, onPrimary #FFFFFF, primaryContainer #DDE9FF, onPrimaryContainer #102A56, background #F6F8FC, surface #FFFFFF, onSurface #17243A, secondary text #43536B, outline #697992 |
| Semantic roles | Success #13613E on #E5F6ED, pending #744600 on #FFF2D6, error #A51D2B on #FDEBED. Pair color with text and icon. |
| Typography | Roboto/system sans. Total 36/44 medium with tabular numerals, headline 24/32, title 18/24, body 16/24, label 14/20, metadata 12/16. Sizes/line heights in sp. |
| Geometry | Spacing 4/8/12/16/24/32 dp, page inset 16 dp, cards 16 dp radius, sheets 24 dp radius, touch targets ≥48 dp. Respect safe drawing and keyboard insets. |
| Components | Top bar, bottom nav, category chips, product row, quantity stepper, IDR amount entry, total/action bar, payment option row, status pill, QR frame, transaction row, account card, empty/error state and confirm dialog. |

Checkout emphasizes the total and the bottom thumb-reachable action. Use neutral white surfaces, thin dividers, restrained blue, and visible disabled and focused states. Keep QR artwork on its original white field without cropping, recoloring, logo overlays, or regeneration. Use a QR readability check, merchant attestation of provenance, and local preview before activation.

The supplied GoPay Merchant screenshot informs the blue header, rounded white surfaces and hierarchy. UMKM-KU uses original content, grouping and navigation.
